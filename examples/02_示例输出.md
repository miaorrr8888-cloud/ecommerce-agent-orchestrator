# 示例输出：4 个机器闸门对模板输入的真实判定

真实运行记录（2026-11-04，Windows，Python 3.13）。输入是**未回填的模板事实**，
用来演示闸门不会因为"文件存在"就放行。

## 输入

```text
runs/Q2-001/
├── PRODUCT_FACTS.json      # cp 自 templates/PRODUCT_FACTS.template.json
└── BLOCKED_FIELDS.json     # cp 自 templates/BLOCKED_FIELDS.template.json
```

## 执行命令

```bash
python scripts/state.py init --sku Q2-001 --root runs --platform douyin
cp templates/PRODUCT_FACTS.template.json runs/Q2-001/PRODUCT_FACTS.json
cp templates/BLOCKED_FIELDS.template.json runs/Q2-001/BLOCKED_FIELDS.json
python scripts/gates.py --run runs/Q2-001 --facts runs/Q2-001/PRODUCT_FACTS.json --gate all
```

## 怎么读这个结果

- **GATE-1 全部 FAIL 是对的**：SKU_ID / PRODUCT_NAME / PRODUCT_IMAGE 都是空串，闸门不会替你猜。
- **GATE-2 `blocked_fields` FAIL**：模板里 `BLOCKED_FIELDS.json` 是空的，等于"没有任何字段标记为拿不到"，
  这在真实项目里几乎不可能——要么你全拿到了，要么你在隐瞒。填了才 PASS。
- **GATE-3 全 FAIL**：还没出片，`decodable`、分辨率、音轨自然都没有。
- **GATE-4 直接告诉你缺哪个文件、完整路径**，不用自己猜目录结构。

## 正常路径

回填真实事实 → 重新跑同一条命令 → GATE-1/2 转 PASS → 出片后再跑 `--gate 3,4`。
**闸门 FAIL 不是 bug，是设计。**
